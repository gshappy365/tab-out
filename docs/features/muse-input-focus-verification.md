# Muse 专项输入焦点适配：实现与验收

日期：2026-10-16。基于 split-screen 的 1.2.0 后续改动；manifest 版本仍为 1.2.0。用户已验收通过并授权将本次代码与文档推送至 split-screen。

## 结果

Muse 原消息输入框已经失焦时，从已有分屏总览鼠标选择、遥控确定或成功返回 Muse 后，扩展主动聚焦其消息框。其他网站沿用原输入焦点恢复策略。

已在日常 Chrome 中启用仅针对 https://muse.ai/* 的可选授权，保留原扩展身份、个人配置与七个命令绑定。

## 实现

- 新增 muse-focus.js，先核对精确 HTTPS origin、目标活动状态及站点授权，再在主 frame 执行聚焦函数。
- 真实 Muse DOM 调查仅检查编辑区结构属性，确认当前中文界面是 textarea[aria-label="消息"]；同时支持明确的英文 Message / Message input 标签，不使用通配 CSS 类名或任意首个输入框。
- 页面已有可编辑焦点时保持原元素和文本选区；否则只聚焦唯一可见、可编辑的 Muse 消息框。没有、禁用、只读或多个候选时不猜测，显示提示。
- 最多在 800ms 内检查编辑区是否出现，未执行常驻观察器；页面不再持有焦点时退出。只在扩展分屏选择/返回完成后触发，菜单、方向及普通页面操作不触发。
- 不读取编辑区 value 或聊天正文，不写入文本、不发送消息，不保存输入内容。返回结果只有状态码。
- 新增 options.html / options.js；总览的“输入焦点设置”进入独立页面，可开启或撤销 Muse 授权。权限请求由点击按钮触发，不自动弹出。

## 权限变化

新增 scripting；optional_host_permissions 仅含 https://muse.ai/*。没有所有网站或子域名授权，没有常驻 content scripts。未授权时不注入，Hark 等其他网站不注入。

用户已明确批准该方案。LCU 点击开启按钮后，Chrome 原生授权框仅显示 muse.ai，批准后设置页显示“已开启”。

## 测试

完整测试在 Chrome for Testing 155.0.8059.84 中 **46 项通过，0 失败、0 跳过**，包含原有分屏/非分屏回归及以下专项覆盖：

- 未授权、非 Muse、子域名、相似域名、非 HTTPS 和已切走标签不执行。
- 真实扩展选择后可聚焦之前没有焦点的消息框，直接键入且搜索框不变。
- 保留原文本选区，菜单回总览，方向不抢焦点，返回到 Muse 再聚焦。
- 多候选拒绝、禁用/缺失拒绝、编辑区延迟出现、脚本权限失效。

隔离浏览器测试只在临时扩展副本中模拟已授予 Muse 权限，并用拦截响应构造页面；发布代码没有必选 host_permissions。真实可选授权另由下述 LCU 验证。

JavaScript 语法检查、git diff --check、发布文件凭证模式扫描通过。无包管理器依赖清单或新增第三方运行依赖，npm/pip 审计不适用。

## LCU 真实 Muse 验收

日常 Chrome 155.0.8059.82，使用现有已登录的 Muse 与 Hark 页面：

1. 原 Muse 输入框为空；点击聊天正文后，AX 焦点为 Muse HTML content，复现原失焦场景。
2. 从总览鼠标点击 Muse，等待 AX 显示消息框获焦；不再点击输入框，直接键入 LCU-MUSE-FOCUS，AX 值准确显示该测试文字。
3. 再点击正文使消息框失焦，菜单 → 确定快捷键后，消息框重新获焦；直接键入 -KEY，值为 LCU-MUSE-FOCUS-KEY，先前草稿保留。
4. 点击正文失焦后，切至 Hark，AX 焦点为 Hark Message input；返回后，Muse“消息”框自动获焦，测试草稿仍完整。
5. 测试文字已清除，Muse 输入框恢复原来的空草稿。未按发送按钮、未按 Enter 发送消息。
6. 最终恢复总览左侧、Muse 右侧布局，消息框仍可输入。重新加载扩展曾移除旧总览，已用直接扩展地址重新配对，未重载 Muse 或 Hark。

真实页面的文本选区追加验收遇到用户前台操作切换，未完成，不能宣称本机选区验收已通过；文本选区保留已有隔离集成测试覆盖。本轮真实网站验证使用原生快捷键而非实体遥控器，SayAll 完整输入链路仍待实机验收。

## 使用与边界

当前电脑已经启用。以后可在总览顶部“输入焦点设置”中关闭，也可重新按 Chrome 提示开启。

仅已有分屏中的总览操作触发专项逻辑；普通 Chrome 标签栏切换不自动聚焦消息框。Muse 修改编辑区标签、将消息框移入 iframe 或添加多个同名编辑区后可能需要更新适配；届时提示并保留页面，不自动挑选其他输入框。

本机实现与本地包包含此前通用输入焦点改动；原 1.2.0 历史发布包保持不变。
