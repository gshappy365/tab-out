# 用受限 macOS 辅助程序设置原生分屏比例

日期：2026-10-17。

Chrome 155 当前公开分屏接口不能设置比例；拆开并重建后实测回到均分。用户保留每窗口一个总览的要求，并选择切换后固定总览 30%、浏览侧 70%。本机隔离原型已验证原生分隔条拖动和原输入框继续键入，用户授权继续正式接入并在隔离环境验证。

扩展继续拥有真实标签选择、分屏会话与输入焦点恢复。每次操作的短期 Native Messaging host 仅对启动它的 Chrome 当前前台窗口执行有界目标比例调整。现有串行命令队列负责排序，不新增常驻服务。设置默认关闭；只有开启后才在已有分屏的选择与返回路径调用辅助程序。

Native host 使用父进程身份、窗口边界与唯一分隔条确认目标；不接受请求指定任意 PID、比例、网址、脚本或键盘操作。原生捕获当前两个原生标签后先回复 prepared，不移动鼠标；扩展重验最初目标分屏后才 commit，原生再核对捕获的标签身份。此握手绑定浏览器标签与原生分屏，防止启动 host 期间用户已切到另一组分屏。host 自行限制截止时间，在拖动中检查用户抢占并保证释放鼠标。扩展通过实际标签宽度验证结果，再恢复浏览侧焦点及现有 Muse 适配。

原生调整失败不回滚已经完成的标签切换，避免因比例问题破坏用户布局或草稿。用户已转到其他窗口或 App 时停止恢复焦点。接受调整时可能移动鼠标和出现短暂均分布局，以保留 Chrome 原生分屏、真实页面状态及单总览结构。

本轮只允许在隔离 profile 注册 host、加载扩展副本和验证真实网站。日常安装、系统级注册、正式签名发布与远端推送均不属于本轮交付。实际验证结果另存报告，不能将本 ADR 的设计目标当成验收通过。

## 2026-10-18 更新：从固定 3:7 改为保留实测比例

用户复核后确认：不需要固定 3:7，只要切换后保持自己拖好的总览宽度即可。实现改为扩展在拆/建分屏前测量当前总览占比，限制在 0.20–0.60，作为 `targetRatio` 传给 host；host 按该目标拖动分隔条，扩展再用真实宽度复核误差 ≤0.02。首次新组合仍为 Chrome 默认均分，用户拖一次后持续沿用。分屏 API 不能写比例这一点未变，因此原生辅助程序仍是唯一实现路径；固定比例、任意比例和任意命令仍不暴露。此变更需要重新构建 helper，ad-hoc 签名变化后必须在系统设置中重新登记辅助功能授权。
